# Linux Basic Commands

Linux Command Line (CLI) หรือ Terminal คือเครื่องมือที่ทรงพลังที่สุดในการจัดการระบบ เซิร์ฟเวอร์ และการพัฒนาโปรเจกต์ต่าง ๆ บทความนี้รวบรวมคำสั่ง Linux พื้นฐานที่ใช้บ่อยและจำเป็นสำหรับนักพัฒนาและผู้เริ่มศึกษา

## 📁 การจัดการไฟล์และโฟลเดอร์ (File & Directory Management)

การนำทางและจัดการไฟล์/โฟลเดอร์เป็นพื้นฐานที่สำคัญที่สุดในระบบ Linux

### คำสั่งที่ใช้บ่อย

| คำสั่ง | คำอธิบาย | Option ยอดฮิต |
|--------|----------|---------------|
| `pwd` | แสดง Path ปัจจุบัน (Print Working Directory) | - |
| `ls` | แสดงรายชื่อไฟล์และโฟลเดอร์ในไดเรกทอรีปัจจุบัน | `-l` (แสดงข้อมูลละเอียด), `-a` (แสดงไฟล์ซ่อน), `-lh` (แสดงขนาดไฟล์ที่อ่านง่าย) |
| `cd` | เปลี่ยนโฟลเดอร์ที่ทำงานอยู่ (Change Directory) | `cd ~` (กลับ Home), `cd ..` (ย้อนกลับ 1 ระดับ) |
| `mkdir` | สร้างโฟลเดอร์ใหม่ (Make Directory) | `-p` (สร้างโฟลเดอร์ซ้อนกันตามลำดับชั้น) |
| `touch` | สร้างไฟล์เปล่า หรืออัปเดต timestamp ของไฟล์ | - |
| `cp` | คัดลอกไฟล์หรือโฟลเดอร์ (Copy) | `-r` (คัดลอกแบบ recursive สำหรับโฟลเดอร์) |
| `mv` | ย้ายไฟล์/โฟลเดอร์ หรือใช้สำหรับเปลี่ยนชื่อไฟล์/โฟลเดอร์ | - |
| `rm` | ลบไฟล์หรือโฟลเดอร์ (Remove) | `-f` (บังคับลบโดยไม่ถาม), `-r` (ลบโฟลเดอร์แบบย่อยทั้งหมด) |

### ตัวอย่างการใช้งาน

```sh
# ดูว่าตอนนี้เราอยู่ที่โฟลเดอร์ไหน
pwd

# แสดงไฟล์ทั้งหมดรวมไฟล์ซ่อน (.env, .git) พร้อมขนาดไฟล์แบบเข้าใจง่าย
ls -lah

# ย้ายเข้าไปยังโฟลเดอร์โครงการ
cd /var/www/my-project

# สร้างโฟลเดอร์ซ้อนกันทีเดียว
mkdir -p src/components/templates

# สร้างไฟล์ว่าง
touch src/components/templates/Layout.tsx

# คัดลอกโฟลเดอร์และเนื้อหาทั้งหมดไปยังไดเรกทอรีใหม่
cp -r src/ dist/backup-src/

# เปลี่ยนชื่อไฟล์หรือย้ายไฟล์
mv old-name.txt new-name.txt
mv temp.log logs/error.log

# ลบไฟล์
rm config.temp.json

# ลบโฟลเดอร์และไฟล์ย่อยทั้งหมดอย่างถาวร (!!! ระวังคำสั่งนี้มาก ๆ !!!)
rm -rf my-old-project/
```

## 📄 การดูและแก้ไขเนื้อหาไฟล์ (Viewing & Editing Files)

การเปิดอ่านและแก้ไขคอนฟิกูเรชันไฟล์ต่าง ๆ บน Server

### คำสั่งที่ใช้บ่อย

| คำสั่ง | คำอธิบาย | ตัวอย่างการใช้งาน |
|--------|----------|-------------------|
| `cat` | แสดงเนื้อหาทั้งหมดของไฟล์ใน Terminal | `cat index.js` |
| `less` | เปิดอ่านไฟล์แบบทีละหน้า สามารถเลื่อนขึ้น/ลงได้ (กด `q` เพื่อออก) | `less large-log-file.log` |
| `head` | แสดงเนื้อหาต้นไฟล์ (Default คือ 10 บรรทัดแรก) | `head -n 20 app.log` (ดู 20 บรรทัดแรก) |
| `tail` | แสดงเนื้อหาท้ายไฟล์ (Default คือ 10 บรรทัดสุดท้าย) | `tail -f app.log` (ติดตามการเขียน log แบบ Real-time) |
| `nano` | Text Editor ขนาดเล็ก ใช้งานง่าย เหมาะกับผู้เริ่มต้น | `nano .env` |
| `vim` / `vi` | Text Editor ทรงพลัง มีปุ่มลัดเยอะ นิยมใช้กันมากบน Server | `vim nginx.conf` |

### ตัวอย่างการใช้งาน

```sh
# ดู log บรรทัดท้าย ๆ และคอยดูบรรทัดใหม่ที่เพิ่มขึ้นมาแบบสด ๆ (กด Ctrl + C เพื่อออก)
tail -f /var/log/nginx/access.log

# แสดงเนื้อหาของไฟล์พร้อมใส่เลขบรรทัด
cat -n config.json

# ค้นหาว่าไฟล์มีอะไรบ้างผ่าน nano
nano /etc/hosts
# (กด Ctrl + O เพื่อบันทึก, กด Ctrl + X เพื่อออกจากโปรแกรม)
```

## 🔍 การค้นหาและกรองข้อมูล (Searching & Filtering)

การตามหาคำบางคำหรือตามหาไฟล์ในระบบที่มีขนาดใหญ่

### คำสั่งที่ใช้บ่อย

| คำสั่ง | คำอธิบาย | ตัวอย่างการใช้งาน |
|--------|----------|-------------------|
| `grep` | ค้นหาข้อความในไฟล์หรือผลลัพธ์จากคำสั่งอื่น | `grep "Error" app.log` |
| `find` | ค้นหาไฟล์และโฟลเดอร์ตามเงื่อนไข เช่น ชื่อ, ประเภท, หรือขนาด | `find . -name "*.js"` |
| `wc` | นับจำนวนบรรทัด คำ และตัวอักษร (Word Count) | `wc -l list.txt` (นับจำนวนบรรทัด) |

### ตัวอย่างการใช้งาน

```sh
# ค้นหาบรรทัดที่มีคำว่า "failed" ในไฟล์ log (ไม่สนใจตัวพิมพ์เล็ก-ใหญ่ ด้วย -i)
grep -i "failed" system.log

# ทำงานคู่กับ Pipe (|) ค้นหาเฉพาะ process ที่ชื่อ "node"
ps aux | grep node

# ค้นหาไฟล์ที่มีนามสกุล .env ในไดเรกทอรีปัจจุบันและโฟลเดอร์ย่อยทั้งหมด
find . -name ".env"

# ค้นหาไฟล์ที่มีขนาดมากกว่า 100MB ในเครื่อง
find / -type f -size +100M 2>/dev/null
```

## 🔐 การจัดการสิทธิ์และการเข้าถึง (Permissions & Ownership)

โครงสร้างสิทธิ์ใน Linux จะถูกแบ่งเป็น 3 กลุ่มหลัก คือ **Owner (u)**, **Group (g)**, และ **Others (o)** โดยแต่ละกลุ่มจะมีสิทธิ์ **Read (r=4)**, **Write (w=2)**, และ **Execute (x=1)**

### คำสั่งที่ใช้บ่อย

| คำสั่ง | คำอธิบาย | ตัวอย่างการใช้งาน |
|--------|----------|-------------------|
| `chmod` | เปลี่ยนสิทธิ์การเข้าถึงไฟล์หรือโฟลเดอร์ (Change Mode) | `chmod +x deploy.sh` |
| `chown` | เปลี่ยนเจ้าของไฟล์หรือกลุ่มของไฟล์ (Change Owner) | `chown -R www-data:www-data /var/www/html` |
| `sudo` | รันคำสั่งด้วยสิทธิ์สูงสุด (Superuser Do) | `sudo apt update` |

### ตัวอย่างการใช้งาน

```sh
# เพิ่มสิทธิ์ให้ไฟล์ deploy.sh สามารถสั่งรัน (Execute) ได้
chmod +x deploy.sh

# ตั้งค่าสิทธิ์แบบตัวเลข (Octal) 
# 755 = Owner อ่านเขียนรันได้ (4+2+1=7), Group/Others อ่านและรันได้อย่างเดียว (4+1=5)
chmod 755 build.sh

# ตั้งค่าสิทธิ์แบบปลอดภัยสูงสุดสำหรับไฟล์คอนฟิก (.env หรือ private key)
# 600 = Owner อ่านและเขียนได้คนเดียว คนอื่นห้ามเข้าถึง (4+2=6, 0, 0)
chmod 600 .env

# เปลี่ยนสิทธิ์เจ้าของโฟลเดอร์เว็บให้เป็นของ User www-data แบบ Recursive (ทั้งหมดข้างใน)
sudo chown -R www-data:www-data /var/www/my-website
```

## 🖥️ การจัดการระบบ ทรัพยากร และโปรเซส (System & Process Management)

การตรวจสอบประสิทธิภาพเครื่อง การใช้ CPU, RAM, Disk และการจัดการ Process ที่ทำงานค้างอยู่

### คำสั่งที่ใช้บ่อย

| คำสั่ง | คำอธิบาย | Option ยอดฮิต |
|--------|----------|---------------|
| `df` | ตรวจสอบพื้นที่ของดิสก์ในระบบ (Disk Free) | `-h` (แสดงผลลัพธ์เป็นหน่วย MB/GB ที่อ่านง่าย) |
| `du` | วิเคราะห์ขนาดของไฟล์และโฟลเดอร์ (Disk Usage) | `-sh *` (สรุปขนาดของแต่ละโฟลเดอร์ในระดับปัจจุบัน) |
| `free` | ตรวจสอบปริมาณการใช้งาน RAM (Memory) | `-m` (แสดงหน่วยเป็น MB), `-h` (อ่านง่าย) |
| `top` | แสดงแผงตรวจสอบระบบและการใช้ทรัพยากรแบบ Real-time | - |
| `htop` | คล้าย top แต่มีหน้าตาที่สวยงามและใช้งานง่ายกว่า (ต้องลงเพิ่ม) | - |
| `ps` | แสดงโปรเซสที่กำลังทำงานอยู่ ณ ขณะนั้น (Process Status) | `aux` (แสดงข้อมูลของโปรเซสทั้งหมดอย่างละเอียด) |
| `kill` | ส่งสัญญาณหยุดหรือปิดโปรเซสโดยใช้ PID (Process ID) | `-9` (บังคับปิดทันที - Force Kill) |
| `killall` | ปิดโปรเซสทั้งหมดโดยระบุชื่อโปรเซส | `killall node` |

### ตัวอย่างการใช้งาน

```sh
# เช็คปริมาณพื้นที่ดิสก์ที่เหลืออยู่บนเครื่อง
df -h

# เช็คขนาดพื้นที่ของโฟลเดอร์และไฟล์ย่อยทั้งหมดในห้องปัจจุบัน
du -sh *

# เช็คแรมที่เหลือและที่ใช้ไป
free -h

# ดูโปรเซสทั้งหมดที่รันอยู่และคัดกรองเฉพาะโปรเซส node
ps aux | grep node

# บังคับหยุดโปรเซสที่ค้างด้วย PID (สมมติ PID คือ 12345)
kill -9 12345

# ปิดทุกโปรเซสของ Node.js ที่ทำงานอยู่
killall node
```

## 🌐 การจัดการเครือข่ายและการเชื่อมต่อ (Network & Connectivity)

คำสั่งตรวจสอบเครือข่าย พอร์ต และดาวน์โหลดข้อมูล

### คำสั่งที่ใช้บ่อย

| คำสั่ง | คำอธิบาย | ตัวอย่างการใช้งาน |
|--------|----------|-------------------|
| `ping` | ทดสอบความล่าช้าและการเชื่อมต่อกับเซิร์ฟเวอร์ปลายทาง | `ping google.com` |
| `curl` | เครื่องมือส่ง Request และดึงข้อมูลผ่านโปรโตคอลต่าง ๆ | `curl https://api.github.com` |
| `wget` | ดาวน์โหลดไฟล์จากอินเทอร์เน็ตเข้ามายังเซิร์ฟเวอร์ | `wget https://example.com/file.zip` |
| `ip a` / `ip address` | แสดงข้อมูลการเชื่อมต่อและ IP Address ของการ์ดจอ/เน็ตเวิร์ก | `ip a` |
| `ss` / `netstat` | แสดงพอร์ตที่เปิดใช้งานและสถานะการเชื่อมต่อเน็ตเวิร์ก | `ss -tulpn` (ดูพอร์ตที่กำลังเปิดรอรับสาย/Listen) |

### ตัวอย่างการใช้งาน

```sh
# ดาวน์โหลดไฟล์และบันทึกชื่อตามต้องการ
curl -o setup.sh https://example.com/installer.sh

# ดึงเฉพาะ Header ของ API เพื่อตรวจสอบ Status Code
curl -I https://google.com

# ตรวจสอบว่าพอร์ตใดกำลังเปิดอยู่ในเครื่อง (มักรันด้วย sudo เพื่อดู PID)
sudo ss -tulpn

# ตัวอย่างเอาต์พุตของ ss -tulpn จะบอกว่ามีบริการใดเปิดรับสายอยู่ เช่น port 80, 443, 3000
```

## 🚀 การโอนย้ายไฟล์ผ่าน SSH (File Transfer via SSH)

บ่อยครั้งที่เราต้องอัปโหลดโค้ดหรือดาวน์โหลดข้อมูล log/backup ระหว่างเครื่องเรา (Local) และเซิร์ฟเวอร์ (Remote) ผ่านการเชื่อมต่อ SSH

### คำสั่งที่ใช้บ่อย

| คำสั่ง | คำอธิบาย | ตัวอย่างการใช้งาน |
|--------|----------|-------------------|
| `scp` | คัดลอกไฟล์/โฟลเดอร์ผ่าน SSH แบบด่วน (Secure Copy) | `scp local-file.txt user@ip:/remote/path` |
| `rsync` | คัดลอกและซิงค์ไฟล์/โฟลเดอร์ ประสิทธิภาพสูงกว่า scp (ซิงค์เฉพาะส่วนต่างและกลับมารันต่อจากที่ค้างได้) | `rsync -avzP local-dir/ user@ip:/remote/path` |
| `sftp` | เปิดการเชื่อมต่อแบบ FTP แต่ปลอดภัยผ่าน SSH สำหรับจัดการไฟล์แบบ interactive | `sftp user@ip` |

> [!IMPORTANT]
> คำสั่ง `scp` และ `rsync` ให้รันจากเครื่อง **Local** (เครื่องคอมพิวเตอร์ของคุณเอง) ไม่ใช่รันภายในเครื่องเซิร์ฟเวอร์ SSH

### 1. การใช้ `scp` (Secure Copy)

#### คัดลอกจากเครื่องคอมเราขึ้นเซิร์ฟเวอร์ (Local -> Remote SSH)
```sh
# คัดลอกไฟล์เดี่ยว
scp /path/to/local/file.txt username@remote_ip:/path/to/remote/directory/

# คัดลอกทั้งโฟลเดอร์ (ต้องใส่ flag -r)
scp -r /path/to/local/folder/ username@remote_ip:/path/to/remote/directory/

# กรณีที่เซิร์ฟเวอร์เปลี่ยน Port SSH (ใช้ -P ตัวใหญ่) และต้องใช้ SSH Key (ใช้ -i)
scp -P 2222 -i ~/.ssh/my_key.pem /path/to/local/file.txt username@remote_ip:/path/to/remote/directory/
```

#### คัดลอกจากเซิร์ฟเวอร์ลงเครื่องคอมเรา (Remote SSH -> Local)
```sh
# ดึงไฟล์จากเซิร์ฟเวอร์ลงมาที่โฟลเดอร์ปัจจุบัน (.) บนเครื่องเรา
scp username@remote_ip:/path/to/remote/file.txt .

# ดึงทั้งโฟลเดอร์ลงมาที่เครื่องเรา
scp -r username@remote_ip:/path/to/remote/folder/ /path/to/local/directory/
```

---

### 2. การใช้ `rsync` (แนะนำสำหรับไฟล์ขนาดใหญ่หรือโฟลเดอร์)
`rsync` มีความเร็วและเสถียรมากกว่า `scp` เพราะมีความสามารถในการโอนเฉพาะไฟล์ที่อัปเดต และแสดงเปอร์เซ็นต์ความคืบหน้า

#### คัดลอกจากเครื่องคอมเราขึ้นเซิร์ฟเวอร์ (Local -> Remote)
```sh
# -a: เก็บข้อมูล metadata ครบ (สิทธิ์ไฟล์, วันที่สร้าง)
# -v: แสดงรายละเอียดขั้นตอน
# -z: บีบอัดข้อมูลระหว่างส่งเพื่อความเร็ว
# -P: แสดงแถบความคืบหน้า (Progress) และรองรับการดาวน์โหลดต่อหากเน็ตหลุด
rsync -avzP /path/to/local/folder/ username@remote_ip:/path/to/remote/directory/
```

#### คัดลอกจากเซิร์ฟเวอร์ลงเครื่องคอมเรา (Remote -> Local)
```sh
rsync -avzP username@remote_ip:/path/to/remote/folder/ /path/to/local/directory/

# กรณีใช้ Port หรือ SSH Key ที่แตกต่างออกไป ให้ระบุด้วย -e
rsync -avzP -e "ssh -p 2222 -i ~/.ssh/my_key.pem" username@remote_ip:/path/to/remote/folder/ /path/to/local/directory/
```

---

### 3. การใช้ `sftp` (Interactive Mode)
เหมาะสำหรับการเข้าไปดูรายชื่อไฟล์และดาวน์โหลด/อัปโหลดเป็นรายไฟล์ด้วยคำสั่งเฉพาะตัว

```sh
# เชื่อมต่อไปยังเซิร์ฟเวอร์
sftp username@remote_ip

# เมื่อเข้าสู่ sftp shell แล้ว (หน้าจอจะขึ้น sftp>)
sftp> ls                         # ดูไฟล์บนเซิร์ฟเวอร์
sftp> cd /path/to/remote/dir     # ย้ายโฟลเดอร์บนเซิร์ฟเวอร์
sftp> lls                        # ดูไฟล์บนเครื่อง Local ของเรา (Local ls)
sftp> lcd /path/to/local/dir     # ย้ายโฟลเดอร์บนเครื่อง Local ของเรา (Local cd)

# ดาวน์โหลดไฟล์จากเซิร์ฟเวอร์ลงเครื่องเรา
sftp> get remote-file.txt

# อัปโหลดไฟล์จากเครื่องเราขึ้นเซิร์ฟเวอร์
sftp> put local-file.txt

# ออกจาก sftp
sftp> exit
```

## 💡 ทริคและคีย์ลัดที่มีประโยชน์ (Useful Shortcuts & Tricks)

เพื่อให้การพิมพ์คำสั่งบน Linux รวดเร็วและสะดวกยิ่งขึ้น

### คีย์ลัดใน Terminal (Keyboard Shortcuts)
- **`Tab`**: กดหนึ่งครั้งเพื่อสะกดชื่อไฟล์หรือคำสั่งอัตโนมัติ (Auto-completion) กดเบิ้ลสองครั้งเพื่อดูคำสั่งทั้งหมดที่เป็นไปได้
- **`Ctrl + C`**: หยุดการทำงานของคำสั่งปัจจุบันที่กำลังวิ่งอยู่ทันที (Abort command)
- **`Ctrl + Z`**: ส่งคำสั่งปัจจุบันไปรันในเบื้องหลัง (Background)
- **`Ctrl + L`** หรือพิมพ์ `clear`: ล้างหน้าจอ Terminal ให้สะอาดเหมือนเปิดใหม่
- **`Ctrl + R`**: ค้นหาประวัติคำสั่งเก่า ๆ ที่เคยพิมพ์ไป (Reverse-i-search)

### การทำงานร่วมกันของคำสั่ง (Pipes & Redirections)
- **Pipe (`|`)**: ส่งผลลัพธ์ (Output) ของคำสั่งแรกไปเป็นข้อมูลรับเข้า (Input) ของคำสั่งถัดไป
  ```sh
  cat logs.txt | grep "Error" | wc -l
  # เปิดไฟล์ logs.txt -> ค้นหาคำว่า Error -> นับว่าคำนี้เกิดขึ้นทั้งหมดกี่บรรทัด
  ```
- **Redirect (`>`)**: เขียนผลลัพธ์ทับไฟล์เดิม (Overwrite)
  ```sh
  echo "hello" > message.txt  # ไฟล์ message.txt จะมีคำว่า hello เพียงอย่างเดียว
  ```
- **Redirect (`>>`)**: เขียนผลลัพธ์ต่อท้ายไฟล์เดิม (Append)
  ```sh
  echo "world" >> message.txt # เพิ่มคำว่า world เข้าไปบรรทัดใหม่ ท้ายคำว่า hello
  ```
- **`history`**: พิมพ์ `history` เพื่อดูประวัติการป้อนคำสั่งทั้งหมดที่คุณเคยใช้งาน
